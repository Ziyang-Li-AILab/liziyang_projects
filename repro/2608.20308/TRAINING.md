# 训练入口与流程说明

官方发布的仓库（`code/`）只有推理：`infer_video.py` 读一段视频，写出手部姿态。论文里的训练器、损失函数、数据混合，发布包里都没有。复现时补上的训练入口是：

```text
liziyang_projects/repro/2608.20308/src/train.py
```

论文设定的启动方式：

```text
python train.py --config configs/repro-default.yaml
```

这条命令假定：已装好带 CUDA 的 PyTorch、Wan 的 DiT 和 VAE 权重、MANO 的 pkl，以及按 `data/` 放好的七个数据集。本机目前不满足这些条件。本机能跑的是另一条更短的脚本 `src/debug_loop.py`，它不是训练入口，文末单独说明。

配置文件是 `src/configs/repro-default.yaml`。它再去读官方的模型配置 `code/options/ace_ego_hand_k.yml`（K-given）。把 yaml 里的 `kfree: true` 并改用 `ace_ego_hand_kfree.yml`，才是 K-free 那一次单独的训练。论文是两个配置各训 20000 步，互不共享权重。

---

## 1. 先建立几个词

一次训练就是重复下面这件事两万次：拿一小段视频，让网络猜双手的姿态，把猜的和标注比一比，按差距改网络的权重。

| 词 | 在这里指什么 |
|---|---|
| 潜变量 | VAE 把像素压成的小张量。81 帧像素对应 21 帧潜变量。网络吃的是潜变量，不吃原始像素。 |
| 槽位 | 左手永远是槽 0，右手永远是槽 1。没有「先检测再匹配」。 |
| `exists_3d` | 这一帧、这个槽位有没有三维标注。有标注（含跑出画面）为 1，数据集根本没标这只手为 0。FreiHAND 只有右手，左手整段都是 0。 |
| `exists_2d` | 这只手的某个关节有没有投影在画面内，并且在相机前方超过 1 cm。出画就是 0。 |
| K | 针孔内参 `fx, fy, cx, cy` 加上图像宽高。训练时来自数据集的标定，不是命令行参数。 |
| 一步（step） | 取一个 batch，算损失，反传，AdamW 更新一次权重。论文一共 20000 步。 |
| batch | 一次送进网络的多段视频。论文是每张 GPU 4 段，16 张 A100，全局 64 段。这 64 段必须来自同一个数据集。 |

## 2. 从 `train.py` 进去之后发生什么

`main()` 按这个顺序做。括号里是真正干活的文件。

### 2.1 读配置、定随机种子、建输出目录

`load_config`（`ace_repro/config.py`）读 `repro-default.yaml`，再把 `ace_ego_hand_k.yml` 挂到 `cfg["model"]`。相对路径都换成相对 `code/` 的绝对路径。

`seed_all` 把 Python、NumPy、PyTorch 的随机数固定成 42。设备写死为 `cuda`。输出目录是 `runs/<配置名>/`，里面会有 `config.yaml`、`train_log.jsonl`、`eval_log.jsonl` 和 checkpoint。

`--debug-mode` 会把总步数改成 10、每步打印、batch 改成 2 段。这是冒烟，不是论文的 20000 步。

### 2.2 建立网络 `ReproModel`

`ace_repro/model.py` 的 `ReproModel` 调用和官方 `GeoDitModel` 相同的构造函数，得到一个 `GeoDiT`：

1. 从磁盘加载 Wan2.2-Fun-5B-Control 的低噪声 DiT 和它的 VAE 配置。骨干大约 50 亿参数，冻结权重用 bfloat16。
2. 在全部 30 个 block 的注意力和前馈上插 LoRA（秩 64）。这些是要训练的。
3. 148 通道的 patch embedding 也要训练（学习率更小）。
4. 第 15 个 block 之后接解码器 `MemorySegmentBetasTransformer`（宽 384，4 层）和 1×1 射线头。
5. 若解码方式是 mixed-PnP，把左右手 MANO 挂到解码器上。MANO 不进优化器，也不进 checkpoint。找不到 pkl 且加了 `--allow-fake-mano` 时，用 `FakeMANO` 代替。`FakeMANO` 只是一副尺寸大致像手的连杆，数字不能和论文比。

`set_train_mode`：解码器和射线头处于 train，Wan 骨干处于 eval（关闭 Dropout）。骨干里 LoRA 和 patch embedding 的 `requires_grad` 仍是 True，所以它们还是会被更新。

三组学习率（论文附录 B.2）：

| 组 | 里面有什么 | 学习率 |
|---|---|---|
| decoder | 解码器、射线头、存在性头 | 2e-4 |
| lora | 骨干里名字含 `lora_` 的张量 | 1e-4 |
| patch_embed | `patch_embedding` | 2e-5 |

### 2.3 准备数据

`build_sources`：

- 正常训练：到 `data/<数据集名>/train/` 下面找 `.pt`。每个 `.pt` 是一整段录像的潜变量加逐帧标注，由转换脚本事先写好。找到的数据集按 yaml 里的权重放进混合器。验证集只认 `data/arctic/test/`。
- `--debug-mode`，或者一个真实数据集都没找到：改走 `SyntheticClips`。用手头的手模型随机摆出一段骨架，画成彩色线图，再用**真实的 Wan VAE** 编码。debug 时 16 段训练、8 段验证，分辨率 480×480，长度 21 帧像素（不是 81）。这只是把管道跑通。

`MixtureLoader`（`data/mixture.py`）每一步做两件事：

1. 用步数当随机种子，按权重抽一个数据集。权重来自论文表 2：HOT3D 18、Re:InterHand 16、ARCTIC 14、OakInk2 14、FreiHAND 14、RHD 14、H2O 10。种子只依赖步数，不依赖 GPU 编号，这样多卡时每张卡会抽到同一个数据集。RHD 没有 MANO，旋转和形状损失是 0；若各卡数据集不同，有的卡反传得到这些参数、有的卡没有，多卡同步会出错。这个「各卡同一数据集」写在加载器里，但 `train.py` 本身没有启动多卡。
2. 从这个数据集里均匀抽 `clips_per_gpu` 段（默认 4），拼成一个 batch。

视频段在 `ClipStore` 里再被切窗：潜变量随机取连续 21 帧，对应大约 81 帧像素的标注。静态图（FreiHAND、RHD）已经是 5 帧，不再切。

一个 batch 里和损失有关的字段：

| 字段 | 形状（大致） | 含义 |
|---|---|---|
| `latent` | `(B, 48, 21, H/16, W/16)` | VAE 潜变量，网络的输入 |
| `K` | `(B, 6)` | `fx, fy, cx, cy, W, H` |
| `go`, `hp`, `betas` | 旋转矩阵和 10 维形状 | MANO 真值。RHD 的 `has_mano` 为假 |
| `trans` | `(B, T, 2, 3)` | 相机系平移真值 |
| `joints_cam` | `(B, T, 2, 21, 3)` | 21 个关节的三维真值，单位米 |
| `joints2d` | `(B, T, 2, 21, 2)` | 用 K 把三维真值投影到 `[0,1]` |
| `exists`, `visible`, `joint_vis`, `has_mano` | 布尔掩码 | 决定哪一项损失算、哪一项不算 |

二维坐标和可见性不是人工再标的一套点，是三维关节加 K 算出来的。

### 2.4 前向：潜变量进，姿态出

`ReproModel.forward`：

**K-given**（默认配置）直接调用官方的 `GeoDiT.forward_emode`：

1. 潜变量当干净输入（σ = 0，时间步 t = 0）。另外 100 个控制通道填 0，拼成 148 通道。
2. 文本条件是缓存好的一句固定英文字幕的 T5 嵌入，不是每段视频各自的句子。
3. DiT 跑到第 15 个 block，取出特征，折成网格。通道是 3072。论文正文写的网格是 16 像素一格；发布代码是 32 像素一格。复现跟代码。
4. 1×1 卷积预测每个格子的射线方向。沿时间取平均，当成这一段视频的一个相机射线场，送进解码器的射线位置编码（`self_ray_pe`）。K-given 的平移解码仍用数据集的 K，不用这个拟合相机。
5. 解码器对每一帧放 48 个 query（2 只手 + 42 个关节 + 4 个 register），空间上对特征做交叉注意力，时间上做双向自注意力（没有因果掩码）。输出长度是这段的像素帧数 T。
6. 输出字典里有：全局旋转、15 个手指旋转、形状 β、`cam_trans`、`exists_3d`、`exists_2d`、直接回归的三维关节和二维锚点。`cam_trans` 的 xy 由 mixed-PnP 从这些预测里解出来，深度是网络直接回归的 `tz`。

**K-free** 不走官方那条「在锚点上采样射线」当唯一解码。`_forward_kfree` 先用预测射线场拟合一个针孔。拟合通过检查，就把这个拟合 K 送进 mixed-PnP 的针孔分支（拟合 K 在这里被 detach，反传不穿过这四个数进解码）。拟合失败（鱼眼，或射线场退化）才退回官方的射线采样解码。`L_fit` 仍用未 detach 的拟合结果，梯度只从视线误差回到射线场。

### 2.5 损失

`ace_repro/losses.py` 的 `compute_losses`。总损失是各项加权和，权重在 yaml 的 `loss:` 下，数字来自论文附录 B.3。

| 项 | 权重 | 在比什么 |
|---|---|---|
| `rot_geodesic` + `rot_mse` | 1 和 1 | 预测旋转和真值旋转的夹角，再加旋转矩阵的均方误差 |
| `betas_l1` | 0.1 | 形状，L1 |
| `joint_rootrel` | 10 | 相对手腕的三维关节。直接回归头和 MANO 读出各算一份 |
| `joint_cam` | 5 | 相机系三维关节 |
| `wrist_cam` | 2 | 手腕在相机系的位置 |
| `img_joints2d` | 1 | 预测的二维锚点和投影真值，单位是归一化坐标 `[0,1]` 上的 L1 |
| `img_reproj` | 1 | 把预测的三维关节用训练 K 再投影，和二维真值比 |
| `img_wrist2d` | 0.5 | 手腕的二维 |
| `cam_trans` | 1 | 解出来的平移和真值平移，L1。梯度穿过 PnP |
| `presence_3d` / `presence_2d` | 0.5 / 0.25 | 存在、可见两个头的二元交叉熵 |
| `temporal_accel` | 0.5 | 预测关节的加速度的 L1：`‖J_{t+1} − 2 J_t + J_{t−1}‖`。公式里没有真值，所以不减去真值加速度 |
| `ray_cosine` | 1 | 预测射线和「用标定 K 反投影格子中心」得到的射线，余弦距离 |
| `fit_bearing` | K-given 为 0；K-free 为 5 | 拟合相机和标定相机在格子上的视线差。前 500 步从 0 线性升到全权重 |

掩码（哪一项在哪一帧算）见第 4 节。那些掩码论文没有逐项写明。

### 2.6 更新权重

默认 `grad_accum = 1`：一个 batch 反传一次。若你只有一张 GPU、又想模仿全局 64 段，应把 `clips_per_gpu × grad_accum` 凑到 64，yaml 里留了这个旋钮，默认没有凑。

然后：

1. 梯度范数裁到 1.0。
2. AdamW 更新三组参数。权重衰减 0.01，作用在所有可训练参数上，没有排除偏置。
3. 学习率：前 200 步从 0 线性升到上面的三个数，之后余弦降到 0，第 20000 步降完。
4. 每 10 步把损失、梯度范数、当前数据集、PnP 接受率写进 `train_log.jsonl`。
5. 每 500 步在验证集上跑 `SegmentScorer`（`eval/metrics.py`），写 `eval_log.jsonl`。debug 模式最多评 32 段。
6. 每 500 步存 checkpoint：解码器、射线头、骨干里 `requires_grad` 的张量（LoRA 和 patch embedding），外加优化器状态。`infer_video.py --ckpt` 能读前半部分；优化器状态是训练续跑用的，推理会忽略。

循环到 `total_steps` 结束。`--resume` 从 `ckpt_last.pt` 恢复步数、优化器和调度器。

## 3. 一步在时间上的顺序（小白版）

把第 137 步想象成下面这 8 句：

1. 加载器掷骰子。假定掷中 ARCTIC（权重 14%）。
2. 从 ARCTIC 的 `.pt` 里抽 4 段录像。每段再随机切 21 帧潜变量，带上对应的 81 帧双手标注和 K。
3. 这 4 段送进 Wan。Wan 在第 15 层交出特征。射线头说出每个格子的视线方向。
4. 解码器用这些特征和数据集的 K，为每一帧写出两只手的旋转、形状、平移、二维点、存在分、可见分。
5. 损失把这些数和 `.pt` 里的标注相减（旋转用夹角）。出画的帧不算二维项。RHD 的 batch 不算旋转、形状和平移项。
6. 损失对权重求导。Wan 的底座权重不求导；LoRA、patch embedding、解码器求导。
7. 梯度太长就剪短，然后按各自的学习率走一小步。
8. 步数变成 138。学习率已经过了预热，开始沿余弦慢慢变小。

两万步之后，checkpoint 里的解码器和 LoRA 就是「训好的模型」。推理时官方脚本加载它，骨干底座仍用原来的 Wan 权重。

## 4. 官方代码里没有、复现时猜的

发布包没有训练循环，所以下面这些不是从官方训练脚本抄的。标签 `[guess]` 的意思是：论文给了原则或给了权重，但没给这个实现细节；写训练器时必须选一个值。选错了，出画和 K-free 的数字会偏。完整清单还在 `gaps_filled.md`，这里只列已经写进训练代码、而且会影响结果的那些。

### 4.1 损失怎么路由

论文说：出画的手也要监督；RHD 的旋转和形状损失保持为 0。没说每一项的掩码。`losses.py` 现在的选择是：

| 决定 | 代码里怎么做 | 为什么这样猜 |
|---|---|---|
| 存在性的 0/1 | `exists`：这一帧这个槽有三维标注则为 1，含出画 | 否则无法做到「出画仍监督」，也无法让 FreiHAND 的左手槽是空的 |
| 可见性的 0/1 | 沿用评测的画面内门控：任一关节投影在图像内且 z > 1 cm | 论文的可见性定义写在评测附录，训练目标没另给一套 |
| 二维三项 | 只在 `joint_vis` 上平均 | 出画没有二维目标。范数用 L1，坐标用 `[0,1]`，因为解码器的锚点就是这个单位。论文没写 L1 还是 L2，也没写像素还是归一化坐标 |
| 旋转、形状 | 只在 `has_mano 且 exists` 上算 | RHD 没有 MANO，这两项为 0，和论文一致。形状对时间取「任一帧有 MANO」 |
| 平移 `cam_trans` | 同样只在有 MANO 的槽上算 | 猜的。PnP 要用 MANO 的规范关节；RHD 没有，所以关掉。论文没明文说关平移 |
| 相对根的三维关节 | `exists` 为 1 就算，含出画，含 RHD | 论文要求出画仍监督三维；RHD 仍有 21 个关节 |
| 相机系关节、手腕里走 MANO 的那一半 | 要有 MANO | 和上一行是猜的分工：直接回归头用 `exists`，MANO 读出用 `has_mano` |
| `L_joint` 的两路 | 直接回归头和「MANO 正向前向得到的关节」都和真值比，再平均 | 论文同时写了 MLP 头和 MANO 损失，没说只监督哪一路 |
| `L_tmp` 作用在谁身上 | 相机系关节 `J_can + cam_trans`，不减真值加速度，也不看出画掩码 | 公式里只有预测。用相机系而不是手腕相对坐标，是猜的 |
| `L_fit` | 所有格子上的视线 L1；拟合失败的样本不计入；前 500 步线性预热 | 权重 5 和 500 步是论文的。格子和 L1 是猜的：拟合就是在这些格子上做的 |
| 拟合守卫的阈值 | `camera.py`：方差下限 1e-6，焦距相对边长在 `[0.35, 3]`，主点在 `[0,1]`，至少 90% 的射线朝前 | 论文只说有方差下限和焦距括号，没给数字 |
| 归约 | 掩码内取平均，而不是求和 | 猜的。求和会让权重随帧数、关节数改变含义 |

### 4.2 优化和日程

| 决定 | 取值 | 依据 |
|---|---|---|
| AdamW 的 β | `(0.9, 0.999)` | PyTorch 默认。论文没写 |
| AdamW 的 ε | `1e-8` | 同上 |
| 余弦衰减的下限 | 0 | 论文只说 cosine decay。猜的是降到 0，不是降到一个很小的常数 |
| 权重衰减 | 0.01，所有可训练参数，不排除偏置和 LayerNorm | 0.01 是论文的。不排除任何参数是猜的 |
| 训练随机种子 | 42 | 推理 yaml 里是 42。训练种子论文没写 |
| 权重 EMA | 不做 | 论文和发布代码都没写 EMA。解码器里的 `shape_ema_logit` 是一段视频内部的形状平滑，不是优化器的 EMA |
| 数据增强 | 不做翻转、颜色、裁剪。官方代码里的 span-dropout 默认关 | 论文没提增强。水平翻转会把左右槽对调，和固定槽位冲突，所以明确关掉 |
| 各 GPU 同一数据集 | `MixtureLoader.source_for_step` 只用步数做种子 | 猜的，为了 RHD 那种「有的损失项没有梯度」在多卡上能对齐。`train.py` 没有真正启动多卡，见第 5 节 |

### 4.3 数据

| 决定 | 代码里怎么做 | 依据 |
|---|---|---|
| 窗口起点 | 在「总潜变量帧数 − 21」里均匀随机 | 论文说按段抽窗口，没说均匀还是按运动幅度。短于或等于 21 帧潜变量的录像不切，整段返回。`gaps_filled.md` 里曾猜「太短就跳过」，实现没有跳过 |
| H2O 的高 | yaml 写成 480（宽 832） | 论文没写缩放后的高。VAE 要求边长是 32 的倍数，720 缩到编码宽 832 之后不是 32 的倍数，所以取了 480。这是猜的 |
| Re:InterHand 分辨率 | yaml 写成 480×480 | 论文没写。猜的 |
| FreiHAND / RHD | 224×224 和 320×320，图像复制成 5 帧 | 「复制成 5 帧」是论文的。用原生分辨率是猜的：它们已经是 32 的倍数 |
| OakInk2 的 MANO | 从 `flat_hand_mean=True` 的关节角里减去 `hands_mean` | 猜这是 smplx 的恒等换算。转换脚本还没写，所以这条还没在数据上发生 |

| HOT3D、OakInk2、HOI4D 的测试片段编号 | 没有 | 论文给了段数，没给编号，恢复不了。不能声称评测集和 Table 1 是同一批片段。HOT3D 这边用的是官方 Clips 划分 |
| H2O / HOI4D 的一部分 MANO | 没有重标 | 论文说是某个未点名的逐帧估计器的伪真值。估计器未知，就不能假装标签和作者的一致 |
| 验证间隔 500 步 | yaml 的 `eval_every: 500` | 由「第 5k 步到第 20k 步之间有 31 个验证 checkpoint」反推，论文没写「每 500 步」这五个字 |

## 5. 相对论文，实现里简化掉或还没接上的

这些不是「猜了一个论文没写的数」，而是训练器故意没做成论文的规模，或者配置写了但代码没读。

### 5.1 `train.py` 这条正式入口

| 简化 | 实情 |
|---|---|
| 单进程、单卡 | `device = torch.device("cuda")`。没有 `DistributedDataParallel`。论文是 16 张 A100（K-free 是 8 张）。加载器留了 `rank` 参数，`train.py` 调用时始终是单卡 |
| 全局 batch 默认不是 64 | `clips_per_gpu: 4`，`grad_accum: 1`。一张卡上一次只看 4 段，不是 64 段。要把梯度累积开到 16 才在「更新前看过的样本数」上对齐，更新次数和噪声都不等于 16 卡同步 |
| `num_workers: 4` 没有被读 | yaml 里有。加载器在主进程里直接 `torch.load`，没有 DataLoader 的多进程 |
| `span_dropout: 0.0` 没有被读 | 训练循环不把潜变量帧打成洞。官方 GeoDiT 有这个钩子，复现训练没接 |
| `eval.penalty_mm: 1000` 没有被读 | 评测器 `SegmentScorer` 对漏检使用论文写的规范 MANO（单位旋转、零姿态、平均形状、平移 0），不用这个 1000 mm |
| 七个数据集的转换器还没齐 | `converters/` 里有 FreiHAND 和 HOT3D。HOT3D 写完了 `clip-001849` … `clip-001853` 这 5 个 `.pt`，`clip-001854` … `clip-001856` 还没编码。ARCTIC、H2O、OakInk2、Re:InterHand、RHD 仍然没有转换器。某个数据源目录空着或没有 `.pt` 时，`train.py` 不会用它；一个真实源都没有时才改走合成骨架 |
| 合成数据不是论文数据 | `SyntheticClips` 画骨架、用真 VAE 编码。debug 模式 16 段、21 帧。可以没有 MANO pkl（`FakeMANO`）。损失和工作流是真的，图像和手模型不是 |
| 扩散辅助损失没做 | yaml 里写了：论文说这项没有消融价值，发布代码里也没有，所以不复现 |
| 验证集不是 Table 1 的全集 | 有 ARCTIC 测试目录就用它，而且按整段录像评，不是论文那 291 个固定的 81 帧片段。其它数据集的官方片段编号缺失。debug 最多 32 段 |

### 5.2 本机调试脚本 `src/debug_loop.py`（更短，不是训练）

这是为了在没有 Wan 权重、没有 CUDA 的 Windows 上能单步看解码器和损失。相对 `train.py` 又砍掉这些：

| 被拿掉的 | 用什么代替 |
|---|---|
| Wan DiT（约 50 亿参数）和 VAE | 一张固定随机数种子的特征图，形状 `(1, 3072, 2, 4, 4)`。3072 是第 15 层特征的通道数；21×15×15 的真网格被缩成 2×4×4 |
| 数据集和渲染 | `make_batch` 用 `FakeMANO` 摆一条 9 帧的双手，K 是写死的。不读视频 |
| 20000 步、三组学习率 | 默认 2 步，解码器和射线头共用解码器学习率 2e-4 |
| GPU | `--device` 默认 `cpu` |
| K-free 拟合 | 不跑。`fit=None`，`fit_bearing` 为 0 |

保留的是官方解码器、mixed-PnP、`FakeMANO`、`compute_losses`，以及「存 checkpoint → 新建模块 → 再加载 → eval 前向」。日志里的 `hand_model=fake`、`backbone=stub` 表示这些数字不能和论文比。

要看论文的训练流程，断点打在 `src/train.py` 的 `while step < sch["total_steps"]` 循环里。要在本机看解码器和损失，断点打在 `src/debug_loop.py` 的 `TapStub.forward` 和 `losses.py` 的 `compute_losses`。
